# 羽球對決 2.5D 🏸

網頁版 2.5D 羽球遊戲：**左手搖桿移動、右手按住蓄力、往方向划動出拍**。單打或雙打（你＋AI 夥伴）對 AI，或開線上好友房跟朋友對打。

## 怎麼玩

第一次玩建議先點選單的「新手教學」。

主選單先選球員、球拍（卡片上是 3D 小圖），按「開始比賽」進「比賽設定」：單打／雙打、難度（簡單／普通／困難／超難／地獄）、場地（或隨機）、每局 11／15／21 分、一局或三戰兩勝、你的球衣顏色和對手顏色（預設隨機），選完按「開始」；上次的選擇會記住。跑位、撲救、擊球方式和畫面聲音在「⚙ 設定」。

| | 手機（直向或橫向） | 電腦 | 手把 |
|---|---|---|---|
| 移動 | 左半邊螢幕按住拖曳 | WASD | 左搖桿 |
| 蓄力 | 右半邊螢幕按住 | 滑鼠按住／空白鍵 | RT |
| 出拍 | 往方向划 | 拖曳滑鼠／方向鍵 | 右搖桿撥出去 |
| 取消（假動作） | 不划直接放開 | 不拖直接放開 | 放開 RT |
| 跳殺 | 點一下再按住 | 連按兩下空白鍵／滑鼠 | 連按兩下 RT |

**跳殺**：連按兩下並按住後，高球（2.3 m 以上）快到時會自動起跳（`GAME.jump.lead` 調時機）；看到起跳後約 0.35 秒往下划，在最高點擊中最好。待命時腳下有青色小圈。跳殺時蓄力不會超過出界線。

**擊球回饋**：擊中後畫面停頓一下（殺球、跳殺更久）；評價 完美／不錯／勉強；揮空會顯示原因；球打過來時腳邊白圈是擊球範圍，變綠代表現在划剛好；發球時會畫出能站的發球區。

按下蓄力時會有圓環波紋、腳下光圈（蓄到出界區變紅）和短震動（Android；iPhone 不支援震動）。按下就立刻開始累積蓄力（`chargeDelay` = 0）。鏡頭角度在 `src/config.ts` 的 `CAMERA` 調整。

划動方向決定球種（遊戲會依擊球點高低自動判斷）：

| 擊球點 | ↑ 上划 | ↓ 下划 | ← → 橫划 |
|---|---|---|---|
| 高（頭頂） | 高遠球 | 蓄力多＝殺球、少＝切球 | 平高球／平抽 |
| 中 | 挑球 | 撲球／下壓／切球 | 平抽 |
| 低（低於網） | 挑球 | 放網／推球 | 平抽 |

蓄力決定落點深度：力道不足會掛網、太大會出界，好球區約佔蓄力條 75%，越靠近底線越難抓。斜著划可以控制落點左右。來球越快反彈力越大，接殺球時輕輕一划就能擋回網前。

球速：殺球、撲球、下壓維持原速；切球、放網、發小球快 1.2 倍；其他球快 1.5 倍（`src/config.ts` 的 `ballSpeedMul`）。初速有上限：殺球／平抽約 230 km/h（`smashMaxSpeed`）、高遠／挑球約 160 km/h（`liftMaxSpeed`）、網前撲球約 58 km/h（`killMaxSpeed`）。

## 球員、球拍、場地、模式

每位球員有特質、每支球拍有取捨（`src/sim/kits.ts`），兩者倍率相乘。「球速」是同一條軌跡飛得更快（不是打更遠）。對手每場隨機換球員和球拍。

| 球員 | 特質 |
|---|---|
| 全能型 | 標準 |
| 重砲手 | 殺球 +12%；跑速 -4%、起步 -6% |
| 網前魔術師 | 切球／放網 +3%、落點誤差 -15%；殺球 -6%、高遠 -5% |
| 推壓手 | 推球／平抽 +6%；高遠 -7% |
| 快腿 | 跑速 +5%、起步 +10%；殺球 -5%、推球 -3% |

| 球拍 | 取捨 |
|---|---|
| 均衡拍 | 標準 |
| 攻擊拍（頭重） | 殺球 +4%；落點誤差 +15% |
| 速度拍（頭輕） | 揮拍判定 +18%、推球 +5%；殺球 -3% |
| 控制拍 | 落點誤差 -30%；殺球 -5% |

- **場地**：櫻花園、夜櫻（燈籠與螢火蟲）、竹林、市場（條紋遮陽棚攤位、蔬果、紅燈籠與燈泡串、騎樓店面）、稻田（隨風一波波起伏的秧苗、倒映天空的水田、農舍、稻草人、白鷺）、海灘（左邊是海、右邊是沙灘：浪花進退、椰子樹、海灘傘、帆船、海鷗）、室內球館（`src/render/environment.ts`、`nightGarden.ts`、`market.ts`、`paddy.ts`、`beach.ts`，全部程序產生，樹會隨風搖）
- **角色外型**：每位球員有不同身高、髮型、頭帶、背號，球拍框顏色跟著球拍、外型跟著球拍種類（`src/render/racket.ts` 的 `makeRacket`：攻擊拍頭大框粗、頂端有深色配重；速度拍細框窄長；控制拍小圓拍頭、拍線密；均衡拍標準）；揮拍有拖尾（殺球金色、跳殺青色）
- **選單 3D 小圖**（`src/render/thumbs.ts`）：用離屏 WebGLRenderer 把真正的球員模型擺成準備姿勢、3/4 角度拍一張（同一台相機、同比例，看得出身高差；選中的球員穿你的顏色、拿你選的球拍），球拍另外拍；轉成 dataURL 快取，閒置 5 秒釋放 WebGL context
- **球衣顏色**（`src/ui/colors.ts`）：8 色色盤；你的顏色預設「原色」（球員自己的顏色）；對手顏色預設隨機（優先挑對比明顯的），跟你太像（雙打還要跟夥伴的深色比）的顏色不能選、開賽時也會自動換掉。巡迴賽對手穿自己球員的原色（太像才換）；線上對戰兩邊都穿球員原色
- **難度**（`DIFFICULTY_PARAMS` in `src/ai/ai.ts`）：超難、地獄比困難反應更快、落點／出拍時機更準、幾乎不碰出界球、更常打空檔且更貼邊線（`aimWide`）、多殺多撲多跳殺、跑不到就撲；地獄跑速／起步再快 5%（`speedMul` > 1 直接加在那位 AI 的 kit 上）。雙打的 AI 也照同一套。自動跑位一律用困難的跑位，不受難度影響。`npx tsx scripts/difficulty-test.ts` 跑「每一級對下一級」的勝率（加 `--doubles` 測雙打、`--sweep=檔案.json` 一次比較多組參數）：

  | 對戰（21 分一局，各 400 局鏡像） | 每分勝率 | 單局勝率 |
  |---|---|---|
  | 普通 vs 簡單 | 87.9% | 100% |
  | 困難 vs 普通 | 90.0% | 100% |
  | 超難 vs 困難 | 78.3% | 100% |
  | 地獄 vs 超難 | 69.6% | 100% |
  | 地獄 vs 困難 | 87.6% | 100% |

  雙打（每隊兩位同難度 AI）：超難 vs 困難 77.6%、地獄 vs 超難 77.0%（每分）。巡迴賽的 `aiLevel(t)` 現在是 0～4（3 = 超難、4 = 地獄），原本 0～2 的關卡不變
- **自動跑位（預設）**：電腦幫你跑位，右邊擊球、左邊「撲」圈往方向划 = 魚躍（設定可改成手動跑位或電腦自動撲）。操作設定在選單的「⚙ 設定」
- **跑位三種**（設定）：**自動**＝電腦幫你跑，平常對手擊球後約 0.24 秒才起步；對手出拍前後左手往猜的方向按住拖（「撲・預判」圈，快速一划才是魚躍），猜對立刻起步、猜錯多等 0.15 秒（`GAME.anticipation`）。**輔助**＝自己推搖桿，方向差不多（約 70° 內）電腦就幫你對準最佳擊球點、推過一次就跑完這一球，沒球要接又沒推時自動回位，擊球範圍 ×1.1。**手動**＝全部自己跑，擊球範圍 ×1.2
- **時機回饋**：每次擊球在上方顯示 過早｜稍早｜完美｜稍晚｜過晚 的時間條（含差幾毫秒）；揮空、掛網、出界（太長／偏左／偏右）也會顯示
- **殺近身**：殺球的球路離身體 0.45 m 內時，平抽抽不出去，只能擋網前（照划的方向，可以彈對角；`GAME.bodySmash`）
- **魚躍撲救**：移動搖桿連按兩下再往某方向划（電腦：Shift + WASD；手把 B）→ 撲出約 1.7 m、擊球範圍往那個方向多 0.5 m、最高 1.5 m，撲到就自動救回網前（放網，撲的時候右手不用操作），之後趴 0.8 秒（`GAME.dive`）。AI 跑不到的低球也會撲（`diveRate`），`npx tsx scripts/dive-test.ts` 看統計
- **擊球時機 = 球質**：完美的高遠球落在底線前約 0.4 m，「不錯」短約 0.4–0.8 m，「勉強」掉到中場；放網／切球時機好就貼網又低（過網高度約 1.58 m），時機差就離網遠又高；殺球、平抽時機好更快。高遠球越短，對手殺球越快（最多 +10%，`GAME.attackSmashBonus`），AI 也越想殺
- **硬伸手接快球**：殺球、撲球、平抽打到離身體路線越遠，硬伸手接的球質越差（側向 0.7 m 內正常、0.9 m 開始變機會球、1.1 m 以上多半是機會球或掛網；`GAME.stretch`）。魚躍撲救不受影響、一定救得過網，AI 也會改用魚躍。`npx tsx scripts/stretch-test.ts` 看對照表
- **下手時機**：放網、挑球（擊球點低於網子）的完美時機比上手晚一點（放開後 0.04 秒擊中最好，上手 0.07；`GAME.idealContactTLow`）。腳邊綠圈、AI、教學暫停都照這個時機
- **中前場殺球**：「殺」搖桿擊中時才決定 — 上手高球（2 m 以上）離網 1.2 m 外都是殺球（不再被當成限速的撲球）；貼網或比網高的低球 = 撲球（約 75–100 km/h）；其他 = 下壓
- **抓球**：中前場（離網 2.3–3.8 m）平飛過來、到網子高度以上的球「只點一下」（平球）→ 搶下來往下壓（`GAME.intercept`）。雙打：對手回的不是殺球（平球、小球、挑高）時維持前後站，前面的人站到約 2.1 m 封網、優先攔截撲／抓
- **球種說明**：設定、暫停畫面的「📖 球種說明」，依目前操作方式列出每種球的手勢與用途（`src/ui/guide.ts`）
- **網前撲球**：網前 2.3 m 內、球高於網時按平球（點一下／左右滑）→ 撲球，約 75 km/h（一般撲球 58），打向中場，反應快的對手約一半救得到（`GAME.netKill`）
- **手動跑位**擊球範圍 ×1.2（`GAME.manualReachMul`），自動跑位與 AI 維持原本
- **場館巡迴賽**：櫻花園站 → 竹林站 → 夜櫻站，每站兩位對手＋館主（`src/modes/tour.ts`）。AI 有打法個性：進攻型、網前型、防守型、平抽快攻、假動作大師（`STYLES` in `src/ai/ai.ts`），也會多打自己球員的強項
- **訓練關卡**：高遠球、殺球、網前、接殺、平抽、跳殺（`src/modes/drills.ts`）
- **雙打（對 AI）**：「開始比賽」→ 模式選「雙打」。你＋AI 夥伴（近側）對兩位 AI，難度、分數、局數、場地、顏色照比賽設定、操作照設定；夥伴和對手每場隨機（夥伴至少「普通」，其他跟難度一樣）。你頭上有黃色箭頭、腳下黃圈；自己這隊穿你的顏色（夥伴深一點），對手兩人穿對手顏色（第二位深一點）
  - 規則：雙打邊線（3.05 m）；發球要落在對角發球區（前發球線～雙打後發球線 5.94 m、雙打邊線內），只有對角的接發球員能接；每邊只能打一拍（打過的那隊兩人都要等對方回球）；落地得分制、比分以隊伍計
  - 發球輪轉（BWF）：發球方分數偶數從右區、奇數從左區發；發球方得分 → 同一人再發、和夥伴換左右；接發球方得分 → 換發球，大家都不換位，站在對的發球區的人發；新的一局由贏的那隊站右區的人先發
  - 分工（`src/ai/doubles.ts` 的 `ballTaker`）：對方每打一拍，就照預測軌跡算隊上誰「最早來得及」接，差不多時照陣型分（前後站：前場球給前面、後場球給後面；並排：球在誰那半邊誰接）。兩位 AI 和你的自動跑位用同一個結果，所以不會搶球也不會都放掉；手動跑位時比較靠近你的球，夥伴會讓給你（分到夥伴的球你腳下不會出現擊球範圍圈）
  - 陣型（`formationSpot`）：自己這隊往下壓（殺、切、放網、平抽、撲）或對方挑高 → 進攻前後站（前場約 2.35 m、後場約 4.6 m）；自己這隊挑高 → 防守左右並排（約 3.9 m 各顧半邊）；打完球回到陣型位置
  - 雙打 AI：落點打兩位對手中間或空檔；網前球高過網帶就撲；像點擊滑放一樣直接指定球種與深度（不用蓄力），誤差照難度。線上對戰只有單打
- **新手教學**（`src/modes/tutorial.ts`）：固定流程教每個搖桿與方向，球快到時暫停等玩家照提示操作，做錯重來；依目前的操作方式與跑位產生步驟。`npx tsx scripts/tutorial-test.ts` 無畫面跑完全部流程
- **平衡**：`npx tsx scripts/balance-test.ts` 跑 AI 對打勝率；目前每個球員×球拍組合對標準組合約 49–53.5%
- **動作**：程序化步法（`src/render/playerModel.ts`、`src/render/anim/`）：腳踩地不滑、併步、交叉步、弓箭步、分腿墊步、準備姿勢、轉身看球、跳殺剪刀腳
- **得分回放**（`src/render/replay.ts`，設定「得分回放」可關）：主動得分（落地得分、發球得分；掛網、出界、發球失誤不播）時，得分後約 0.8 秒播約 3 秒的精彩回放：擊球瞬間慢動作、鏡頭從擊球員右後方跟著球出去，再切到落點旁貼地特寫，擊球聲、殺球特效、落地爆炸跟著重播；上下黑邊、「精彩回放」標籤、球種＋球速，點一下或按任何鍵跳過。比賽每個 tick 把畫面要的狀態錄進 5 秒的環形緩衝區，回放時畫面讀另一個「檢視用」的 Match，比賽本身暫停不動（模擬完全不受影響）。線上、教學、訓練不播。`npx tsx scripts/replay-test.ts` 無畫面驗證有回放／沒回放的比賽結果一模一樣

### 音效（`src/audio.ts`，全部即時合成，不用音檔）

- 擊球（拍線脆響＋軟木「啵」，殺球有爆裂感、完美有「叮」）、揮拍破風、掛網、落地、球鞋急停的吱吱聲、跳殺落地
- 觀眾掌聲（回合越長越熱烈）、裁判中文報分（瀏覽器內建語音，「5 比 3，局點」）
- **每個場地的音效都不同**（`PROFILES` in `src/audio.ts`）：
  - 空間感：室內球館大殘響＋預延遲；市場短殘響＋店面彈回來的回音；竹林柔而散；櫻花園／夜櫻乾淨；稻田、海灘最開闊幾乎沒有殘響
  - 腳下：室內運動地板吱吱叫最響；戶外球場墊的吱聲短而軟，加上鞋底磨到沙土的沙沙聲；落地聲有彈性木地板、空心木棧台（海灘）、悶悶的泥土（稻田、竹林）、紮實的水泥地（市場）
  - 觀眾：室內滿場掌聲＋歡呼＋口哨；市場攤販拍手、吆喝、敲鍋子；海灘一小群人拍手、手指口哨、「呼～」；稻田幾個農夫稀稀落落地拍；櫻花園／夜櫻有禮貌的輕拍；竹林兩三個人輕輕拍。輸分時有觀眾的地方會「唉～」

- 場景環境音：櫻花園鳥叫、竹林風聲與竹子敲擊、夜櫻蟋蟀、市場人聲嘈雜／攤販吆喝／碗盤聲、稻田蛙鳴蟲鳴與微風、海灘一波波的浪聲與海鷗、室內觀眾席
- 背景音樂（設定 →「背景音樂」選，選了馬上換成那首；「▶ 試聽」從頭播，音樂關著也會播 20 秒），比賽中自動變小聲：
  - **依場地自動**（預設）：五聲音階撥弦即興，依場地換音階與速度（櫻花園／夜櫻都節音階、竹林陽音階、室內明亮快板、市場宮調＋輪指、稻田小調慢板、海灘反拍刷弦）
  - 五首寫好的曲子（`MUSIC_TRACKS`，和弦進行＋旋律＋低音＋鼓，循環播放）：**櫻花撥弦**（古箏＋尺八風笛子、太鼓，D 都節音階，84 BPM，16 小節）、**熱血運動**（運動動畫風：銅管主旋律、強力和弦刷弦、搖滾鼓，副歌走王道進行 IV–V–iii–vi，D 大調，140 BPM，24 小節）、**輕快電子**（8-bit 脈衝波主旋律、16 分音符琶音、八度跳貝斯、副歌四拍大鼓，F 大調，120 BPM，16 小節）、**Lo-fi 放鬆**（FM 電鋼琴九和弦／十三和弦、拇指琴旋律、搖擺 boom-bap 鼓、錄音帶晃動，E♭ 大調，82 BPM，16 小節）、**海島 Bossa**（尼龍吉他照 bossa 切分節奏刷和弦、低音大提琴、鋼鼓旋律、沙鈴，D 大調，100 BPM，16 小節）
  - 合成：Karplus-Strong 撥弦（低通過的激發、音準用 playbackRate 補準、去直流）、減法合成（鋸齒／方波／脈衝波＋低通；和弦共用一個濾波器）、FM 電鋼琴、鼓（正弦掃頻大鼓、雜訊＋三角波小鼓、高通雜訊鈸）。排程器每 60 ms 往前排 0.3 秒；每首曲子有自己的匯流排，換曲時淡出後整串拆掉
  - 響度：每首用 `gain` 校正到差不多大聲（K 加權約 -36 dBFS，跟以前的音樂一樣、在音效底下）。`renderMusic()` 可以用同一套程式離線算出一段（OfflineAudioContext），拿來做試聽檔或檢查音量
- 選單可分別開關音效、音樂、裁判報分。iPhone 靜音鍵開著也會出聲（Safari 17+）

### 兩種擊球方式

- **蓄力划動**（預設）：右手按住蓄力、往方向划動出拍；點一下再按住 = 跳殺
- **點擊滑放**（不用蓄力）：右手按住往上滑放開 = 高遠球／挑球、往下 = 切球／放網（上手或下手依擊球點高低自動判斷：`autoDepth` in match.ts）；左右 = 平抽、只點不滑 = 平球（球快到身邊才出拍；網前高於網 = 撲球）；放開的那一刻出拍，放開時機決定球的品質。右手上方的「殺」搖桿：往下或左右滑放開 = 殺球（左右瞄準，前場自動撲球）、往上滑放開 = 假殺真切、只點不滑 = 直線殺球；點一下再按住 = 跳殺（電腦：空白鍵殺球）

## 線上對戰（好友房）

選單「線上對戰」→ 建立房間 → 在「建立線上房間」選選手、球拍、**單打、雙打（雙方各帶一個 AI 隊友）或雙打（4 人）**、場地、分數、局數（雙打再選 AI 隊友／AI 補位強度）→ 把 4 碼房號或分享連結（`?room=房號`）傳給朋友。加入的人進房前可以按「更換選手」。先進房的是房主，模式與規則照房主；雙方各用自己的球員、球拍、球衣顏色、操作方式。

線上雙打：每支手機控制自己這一隊（自己＋自己的 AI 隊友），對方那隊的兩個人都照網路訊息；球員編號雙方都把自己當 0 號、隊友 2 號，傳過去 xor 1（`scripts/online-test.ts 60 2 doubles`）。真人 2 對 2 是「雙打（4 人）」（見下面）。

- **伺服器**（`server/`）：Cloudflare Worker + Durable Object，一個房號一個物件；2 人房只轉送訊息、不跑遊戲邏輯；4 人房另外裁決會影響比分的事件（見下面「雙打（4 人）」）。WebSocket Hibernation，免費方案就夠；連線網址帶 `?cid=`（每個分頁一個連線編號，存在 sessionStorage），同一個 cid 重新連上時舊的連線作廢，不會卡著「房間滿了」
- **同步**（`src/net/sync.ts`）：兩邊各自模擬整場比賽、都把自己放在畫面下方（收到的座標 x、z 反號）
  - 自己的位置每秒送約 18 次，對方外插＋平滑
  - 擊球方送「擊球點＋初速」，對方從同一點發出（軌跡確定）再補上單程延遲（ping 量）
  - 每一球由**接球方**判定得分，擊球方等判定（`await` 階段），所以不會兩邊判得不一樣
  - 線上沒有擊中停頓（不然兩邊時間會越差越多）；暫停畫面時比賽照常進行
  - **延遲處理**：收到對方擊球不往前補（接球方拿到完整的反應時間，這一球本來就由接球方判定）；自己打過去的球在本機整段平均放慢 T/(T+2×單程延遲)，對方回球時球剛好在他球拍附近，不會「快落地又瞬移回來」（`GAME.online`）；剩下的小誤差畫面上 0.1 秒滑順接過去。`scripts/online-test.ts` 會印出瞬移距離（80 ms 單程：中位約 0.17 m）
  - **斷線**：自動重連（切到別的 App 分享房號、網路不穩）；比賽中有人斷線或按了離開，**不會把留下來的人踢出去**：比賽暫停，跳出面板（倒數 20 秒，時間到改成一直等）：「AI 接手繼續」（2 人房 = 對手那隊改由本機 AI 打、房間還開著，變成對 AI 的比賽）、「繼續等待」（顯示房號＋分享連結讓他回來）、「離開」。對方回來（重新整理網頁也可以）→ 比賽狀態最新的那一邊（一直都在 > 斷過線 > 沒有）從目前比分重新發球；他重新整理過就先送 `start`（`rj`）讓他照這場的設定重建；AI 正在代打就等這一分打完再換回來
  - **回到剛剛的房間**：進房／比賽中把房號、連線編號、時間存在 localStorage（`badminton.rejoin`，依連線編號分開存、10 分鐘內有效）。同一個分頁重新整理（或手機把網頁回收後再打開）→ 自動回去；新分頁、或自己按了離開 → 主選單多一個「回到剛剛的房間 XXXX」按鈕。比賽中按「回主選單」要再按一次確認（對手會看到「對手離開了」和同樣的選擇）
- **雙打（4 人）**：2 對 2，每個人控制自己那一位（座位 0、2 = A 隊，1、3 = B 隊）
  - **大廳**：建房的人是房主；進房的人自動坐到真人比較少的那隊；每個座位顯示名字、球員、球拍、跑位、準備；可以「換到這裡」（空位或 AI 補位的位置）、按「準備好了」；房主可以把空位設成「AI 補位」，有 2 個真人以上就能按開始（剩下的空位自動由 AI 補）。AI 補位由房主的手機模擬
  - **跑位**：每個人用自己的設定（自動／輔助／手動，自動跑位照雙打分工 `ballTaker`）；房主勾「全員手動跑位」就全部手動
  - **座位 → 本機編號**：每支手機都把自己放在畫面下方：本機球員編號 = 座位 xor 自己的座位（自己 0、隊友 2、對手 1、3）；訊息裡的座標都是「A 隊在 z>0」的標準視角，B 隊的人整個鏡像（`src/net/sync4.ts`）
  - **伺服器裁決**（`server/src/arbiter.ts`，伺服器和測試共用）：擊球、落地都送伺服器（`ev`，帶 `re` = 回應第幾個已裁決事件、`ct` = 沿著來球飛了多久才擊中、`d` = 擊球時離球多遠），同一個 `re` 只採用一個：**最早擊中的贏，差不到 0.03 秒就比誰離球近**；第一個候選到了開 60 ms（擊球）／150 ms（落地）的窗口收集，窗口結束才決定；同一隊兩人都在同一支手機上（房主＋AI 隊友、發球）不可能搶球就馬上決定。裁決結果蓋上序號廣播給所有人（`acc`，包含送出的人），大家照同樣的順序套用 → 比分一定一樣。開賽／繼續比賽時換新的 `ep` 重設序號（舊的事件丟掉）
  - **搶先顯示＋還原**：自己擊球本機馬上打出去（不用等伺服器），被別人搶先（隊友先打到、球先落地）就還原成擊球前、改套用被採用的（腳邊飄「隊友先打到」）
  - **落地判定**：照這一球的確定軌跡（擊球點＋初速算出的 prediction）判，跟本機有沒有放慢無關，所以每支手機送出的判定都一樣；比分只從伺服器採用的落地事件來
  - **不瞬移**：打出去的球在「接球的人在別支手機上」的手機整段放慢，讓他的回擊傳回來時球剛好飛到他的擊球點（預估擊球點用雙打分工；要多等 = 他那支手機比本機晚多久開始看到這球＋他到伺服器＋裁決窗口＋伺服器到本機，各座位的延遲放在狀態訊息裡）；打向自己這隊、分給遠端隊友接的球，到隊友球拍附近時本機放慢等他的擊球（`GAME.quadHold`）。`scripts/online4-test.ts` 印出瞬移距離（四台 30–150 ms：中位約 0.1–0.2 m）
  - **斷線**：大家一起暫停；帶大家繼續的人（房主；房主斷線了 = 座位號碼最小、還連著的真人）可以按「AI 接手繼續」讓斷線的人由 AI 代打（房主不在時他接手當房主）；斷線的人回來：座位還在 → 人齊了就從目前比分繼續；被 AI 代打 → 這一分打完還給他
- **遊戲大廳**（線上對戰 →「遊戲大廳」，或網址加 `?lobby`）：列出所有「公開到大廳」的房間：房號、房主、模式（單打／雙打（AI 隊友）／雙打（4 人））、場地、分數／局數、人數 `n/2` 或 `n/4`、狀態（等待中／比賽中＋目前比分／已結束）、觀眾數；有空位就能「加入」，隨時都能「觀戰」。名單每 3 秒用 `fetch` 拉一次（`GET /lobby`，JSON `{ rooms: LobbyRoom[] }`）。建立線上房間時「公開到大廳」預設開，選「只用房號」就不會列出來（照樣可以用房號加入或觀戰）
  - 伺服器（`server/src/lobby.ts` 純邏輯 + `index.ts` 的 `Lobby` 物件）：一個 Lobby Durable Object 當名單。房主（4 人房 = 帶大家繼續的人）在連上、開打、每一分、比賽結束時送 `lob`（公開與否、名字、模式、場地、規則、狀態、比分；不轉送給別人），Room 物件存起來、合併自己知道的玩家數和觀眾數，有人進出也算一次變動，**2 秒內合併成一次**（`Coalescer`）用 DO RPC `upsert` 整筆送給 Lobby；等待中沒有訊息往來時每 30 秒用 alarm 心跳一次；房間空了或不公開就 `remove`。Lobby 超過 75 秒沒更新的當作消失（列名單時順便清掉），名單也存在 storage，物件被回收再醒來還在。免費方案的請求數：每個房間最多每 2 秒一次更新＋每 30 秒一次心跳，比賽本身的訊息不會多出任何請求
- **觀戰**：大廳的「觀戰」、房號旁的「觀戰」、或網址 `?spectate=房號`。觀眾沒有座位、不算人數、沒有操作（搖桿、暫停鍵都不顯示，直向也不留搖桿區），用轉播鏡頭（不跟著哪位球員，稍微跟著球；「換邊」可以把另一隊換到畫面下方），記分板兩邊都是真名（雙打是「A＋B」），字幕、得分橫幅都是中立的；2 人房、4 人房都能看，中途進來也可以，離開不影響玩家。玩家在房間畫面看得到「觀眾 N」、比賽中左上角有小標籤。得分回放跟線上一樣不播
  - 伺服器：連線網址帶 `?spec=1` 就標成 `spectator`（每房最多 20 人，滿了回 `full`）；玩家送的訊息都轉一份給觀眾（`ping`／`pong` 不轉），4 人房的裁決結果 `acc` 也給；觀眾送的只接受 `ping`（伺服器直接回 `pong`）、`spec-hello`（轉給玩家）、`bye`，其他全部丟掉，裁決器也不會看到，所以觀眾不可能影響比賽；玩家回的快照 `snap` 只轉給觀眾；觀眾進出就告訴玩家人數（`spec`）
  - **2 人房的訊息怎麼換算**（`src/net/spectate.ts`）：2 人房每支手機都把自己放在 z>0、對方是 1 號，座標是「送出方自己的視角」，得分判定（`pt`）也只由接球方送、`w`／`sc` 都是「以送出方來看」；觀眾同時收兩邊的訊息，所以伺服器轉給觀眾的每一則都多標 `fr`（`h` = 房主送的、`g` = 加入的人送的）。觀眾一律用「標準視角」：房主 = 球員 0（AI 隊友 2）、加入的人 = 1（AI 隊友 3），房主那隊在 z>0。房主送的座標、球員編號照用；加入的人送的 x、z 反號、編號 xor 1（跟房主收到時一樣）。`pt`：`fr=h` 時 `w='me'` = 房主贏、`sc/gm` 直接是 [房主, 加入的人]；`fr=g` 時反過來。觀眾自己不判分（每一球落地進 `await`），比分、局數以 `pt` 送來的為準（`Match.applyAbsoluteVerdict`，漏接一分也會對回來）；`resume` 的 `srv` 也照 `fr` 換算。4 人房的訊息本來就是標準視角（座標 A 隊在 z>0、`st`／`ev` 帶座位），不用標，用 `QuadSync` 的觀眾模式（四個座位都是遠端、不送事件）套用裁決結果
  - **中途加入**：觀眾連上就送 `spec-hello`，由房主（2 人房房主斷線中就由加入的人；4 人房 = 帶大家繼續的人）回 `snap`：2 人房 = 兩邊的 hello（球員、球拍、顏色、AI 隊友）＋這場的規則＋比分＋發球的人；4 人房 = 名單＋比分＋發球區＋裁決器的 `ep` 和已裁決到第幾個事件 `q`（快照還沒到就先收到的 `acc` 會暫存，建好再補套用）。觀眾照快照建比賽，從下一球開始看（位置、擊球都走原本的訊息流）。之後 2 人房的 `start`（含再來一場、斷線回來重建）、`resume`，4 人房的 `go`、`resume4` 觀眾也直接照著重建／繼續
  - 限制：2 人房「AI 接手」期間那支手機不送任何訊息，觀眾會停在最後的畫面，對手回來繼續後才會跟上；觀眾沒有「回到剛剛的房間」
- **測試**：`npx tsx scripts/online-test.ts 60 3`（兩台假手機、單程 60 ms，加第三個參數 `drift` 模擬掉幀；加 `drop` 測斷線 → AI 接手 → 重新整理回來；加 `spec` = 打到 5 分時一位觀眾進房，最後比分要跟房主一致）；`npx tsx scripts/online4-test.ts 3 4h`（四台假手機＋真正的裁決器，每台 30–150 ms＋抖動、偶爾故意兩個隊友搶同一球；`2h` / `2hs` = 兩個真人＋房主模擬兩個 AI；加 `drop` 測斷線、AI 代打、重新整理回來還座位；加 `spec` = 觀眾中途進房）；`npx tsx scripts/lobby-test.ts`（大廳名單：整筆取代、過期清除、排序、節流合併）；瀏覽器測本機伺服器：`cd server && npm run dev`，網址加 `?server=local`（`?server=local:8797` = 指定連接埠）
- **部署伺服器**：`cd server && npx wrangler deploy`（要先 `npx wrangler login`；大廳是新的 Durable Object class `Lobby`，`wrangler.toml` 的 migration `v2` 會一起建）。改了訊息格式記得把 `src/net/protocol.ts` 的 `PROTOCOL` +1。先部署伺服器再推網頁：舊網頁對新伺服器完全相容（不會送 `lob`、不會用 `?spec=1`），新網頁對舊伺服器則大廳連不上、觀戰會被當成玩家

## 開發

```bash
npm install
npm run dev        # http://localhost:5173/badmiton-project/
npm run build      # 輸出到 dist/
npx tsx scripts/sim-test.ts normal 80   # 無畫面測試：擊球求解器 + AI 對打統計
npx tsx scripts/doubles-test.ts normal 8 21   # 雙打：四個 AI 對打，檢查發球輪轉、對角接發、每邊一拍、雙打線、分工、陣型、勝率
npx tsx scripts/difficulty-test.ts            # 難度階梯：每一級對下一級的每分／單局勝率（--doubles 測雙打）
npx tsx scripts/replay-test.ts normal 21      # 得分回放：有回放／沒回放的比賽一模一樣、只有主動得分才播、長度約 3 秒
```

推到 `main` 會由 GitHub Actions 自動部署到 GitHub Pages。

## 程式結構

- `src/config.ts` — 球場尺寸、物理、手感參數（調手感改這裡）
- `src/sim/` — 遊戲邏輯，和畫面完全分開（線上對戰兩邊各跑一份）
  - `physics.ts` 羽球空氣阻力物理、落點預測、擊球軌跡求解
  - `shots.ts` 划動方向 → 球種、蓄力 → 落點
  - `match.ts` 比賽規則：發球、得分、掛網、出界、局數；單打 2 人、雙打 4 人（`players[id]`，0、2 號近側一隊，1、3 號遠側一隊，隊伍 = `id % 2`；`score`／`games` 以隊伍為索引）
- `src/ai/ai.ts` — AI 對手（預測落點 → 跑位 → 選球 → 蓄力出拍），用跟玩家一樣的輸入
- `src/ai/doubles.ts` — 雙打分工（這球誰接）與陣型站位，AI 夥伴、AI 對手、玩家的自動跑位、畫面都用它
- `src/input/controls.ts` — 觸控雙搖桿／鍵鼠／手把
- `src/net/` — 線上對戰：`protocol.ts` 訊息格式、`sync.ts` 2 人房比賽同步、`room.ts` 房間連線與斷線回來的紀錄；4 人房：`quad.ts` 名單與座位、`sync4.ts` 比賽同步（裁決、搶先、還原）、`session4.ts` 照名單建比賽；`spectate.ts` 觀眾端（照訊息模擬、快照）
- `server/` — 房間伺服器（Cloudflare Worker）；`arbiter.ts` = 4 人房的裁決器；`lobby.ts` = 遊戲大廳的名單與節流
- `src/render/` — Three.js 畫面（球場、球員、羽球、影子、拖尾）
- `src/ui/hud.ts` — 記分板、蓄力條、球種文字
